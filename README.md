# Weather Companion

Финальный проект по Android-разработке. Основа — приложение погоды из предыдущих домашних работ: поиск городов через Open-Meteo, прогноз через Яндекс Погоду, экран деталей, навигация и реактивная работа с локальной базой.

## Что добавлено

- экран истории недавно открытых городов;
- экран настроек с тёмной темой, единицами температуры и выбираемым TTL кэша;
- персональный раздел «Мои погодные планы»;
- offline-first поиск и показ последней сохранённой погоды;
- фоновое обновление погоды для городов из личных планов;
- тесты новой бизнес-логики, экранного состояния и offline/background-поведения.

## Пользовательские данные

Room хранит города, погодный кэш, историю просмотров и личные планы. План — самостоятельная сущность, связанная с городом: пользователь задаёт название, заметку и дату, редактирует их, меняет статус и удаляет запись. Настройки приложения хранятся отдельно в DataStore.

## Законченные сценарии

1. Пользователь ищет город, открывает детали, получает актуальную погоду, а город появляется в истории. При недоступной сети поиск и детали используют сохранённые данные Room.
2. Из деталей города пользователь создаёт личный план, добавляет заметку и дату, затем редактирует его, переводит между состояниями «Запланировано», «Выполнено», «Отменено» или удаляет.
3. Пользователь меняет тему, единицы температуры и срок актуальности кэша. Настройки восстанавливаются после перезапуска и непосредственно меняют интерфейс и политику получения данных.

## Offline-first

Сеть используется для обновления. Результаты поиска и погода записываются в Room, а UI читает сохранённые пользовательские данные реактивно через Flow. При сетевой ошибке репозиторий возвращает подходящие города и последнюю погоду из локального кэша. TTL из DataStore определяет, можно ли сразу использовать сохранённую погоду или требуется обновление.

## Фоновая обработка

WorkManager каждые 6 часов запускает уникальную задачу при наличии сети. Задача обновляет погодный кэш для всех городов, связанных с личными планами. При частичной сетевой ошибке Worker запрашивает повторный запуск.

## Тесты

- CachePolicyTest проверяет TTL и решение о фоновом обновлении;
- PlanRulesTest проверяет смену экранного состояния планов и влияние настройки единиц температуры;
- WeatherRepositoryOfflineTest проверяет возврат данных Room при сетевой ошибке.

## Технологии

Kotlin, Jetpack Compose, Room, DataStore Preferences, WorkManager, Retrofit, Coroutines/Flow, JUnit и MockK.
